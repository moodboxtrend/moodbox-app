# MoodBox — Flutter App

A pure content-viewer app (Jokes, Recipes, Stories, Wallpapers, Videos) that reads from the
MoodBox Admin Panel's public API. **No login, no account system, no admin features** — this
app only displays what's marked Active/Published in the admin panel.

---

## 1. Important: I could not compile-check this code

This sandbox doesn't have the Flutter/Dart SDK or access to pub.dev, so unlike the admin
panel (which I actually built and verified), **this Dart code has not been run through
`flutter analyze` or `flutter build`**. It's written carefully and follows standard package
APIs, but please do the following before you rely on it:

```bash
flutter create moodbox_app        # generates android/, ios/, and default files
cd moodbox_app
# replace the generated lib/ and pubspec.yaml with the ones from this project
flutter pub get
flutter analyze                    # fix anything it flags
flutter run
```

Test on a real device or emulator early, especially: wallpaper download/set-wallpaper,
video playback, and image loading — these depend on native platform plugins I couldn't
execute here.

## 2. Point the app at your backend

Edit `lib/core/constants/api_constants.dart`:

```dart
static const String baseUrl = 'https://your-backend-domain.com/api/public';
```

This must be your **deployed** backend (not `localhost`) before you release — an emulator
can reach your computer's localhost, but real users' phones cannot.

Also set `AppConstants.privacyPolicyUrl` and `termsUrl` in `lib/core/constants/app_constants.dart`
— see the Play Store section below, this is not optional.

## 3. Required Android permissions

Copy the contents of `android_manifest_snippet/AndroidManifest_additions.xml` into
`android/app/src/main/AndroidManifest.xml` (generated by `flutter create`), inside the
`<manifest>` tag.

## 4. What's implemented

- **Home** — category quick-links, Featured & Trending carousels
- **Explore** — all active categories in a grid
- **Category feed** — subcategory filter chips + infinite-scroll list (Jokes/Recipes/Stories)
  or grid (Wallpapers/Videos)
- **Post detail**, rendered differently per content type:
  - Joke / Story → article view with rich HTML content
  - Recipe → prep/cook time, servings, difficulty, ingredients, numbered steps, tips, nutrition
  - Wallpaper → full-screen zoomable viewer, Download to gallery, Set as Wallpaper (home/lock/both)
  - Video → in-app YouTube player, or a direct file player for Direct Upload/Vimeo/Other links
- **Search** — debounced live search across all content
- **Favorites** — saved locally on-device (no login needed); tied to a bookmark icon that
  respects each post's `allowSave` flag from the admin panel
- **Settings** — light/dark/system theme, social links (pulled from admin Settings), Share app,
  Privacy Policy / Terms links, app version
- View counts increment automatically when a post is opened; Save/Share actions ping
  lightweight analytics endpoints (fire-and-forget, never blocks the UI)

## 5. Known limitations / things to decide before launch

- **Vimeo / "Other Link" videos** only play in-app if the URL is a *direct video file*
  (`.mp4` etc.). A normal Vimeo watch-page URL won't play in the built-in player — either
  only use YouTube links in the admin panel, or add a WebView fallback for those two sources.
- No offline caching of post content yet — every screen re-fetches from the API. Fine for a
  v1; consider adding a local cache (e.g. `hive` or `sqflite`) later if users are on patchy connections.
- Favorites only store post IDs — if a post is later unpublished or deleted from the admin
  panel, it will quietly disappear from someone's Favorites list (this is intentional and correct).

## 6. Play Store publishing checklist

This app is well-suited for Play Store approval (no login, no ads, no user-generated content,
no sensitive permissions) but these are **not automatic** — you must still do them:

### Must-do before submitting
- [ ] **Host a real Privacy Policy** at a public URL and put it in `AppConstants.privacyPolicyUrl`.
      Google **requires** this for every app, even ones with no login. It must disclose:
      what data you collect (this app sends no personal data to your backend — only anonymous
      view/save/share counts tied to a post, not a user), and that images/wallpapers are stored
      locally.
- [ ] Add the same Privacy Policy URL in **Play Console → App content → Privacy Policy**.
- [ ] Complete the **Data Safety form** in Play Console. For this app's default setup, you can
      truthfully declare: no personal data collected, no data shared with third parties beyond
      Cloudinary (image hosting/CDN) and your own backend. Update this if you add analytics/ads later.
- [ ] Complete the **Content Rating questionnaire** (IARC) — likely "Everyone" or "Teen"
      depending on story/joke content; be honest about any mature language/themes in your posts.
- [ ] Set a **target API level** meeting Google's current minimum (check Play Console —
      this number changes yearly; recent Flutter + recent Android Studio/Gradle keeps this current
      automatically in most cases).
- [ ] Generate a proper **release signing key** (`keytool -genkey ...`) and configure
      `android/app/build.gradle` — do NOT ship the debug signing config.
- [ ] Test the **Set Wallpaper** and **Save Image** flows on a real Android 13+ device — these
      are the two features most likely to trip a review if permissions aren't declared/justified
      correctly (the manifest snippet above already scopes them correctly for modern Android).
- [ ] Remove/replace all `TODO` placeholders in `api_constants.dart` and `app_constants.dart`.

### Good practice, not blocking
- [ ] Add a proper app icon (`flutter_launcher_icons` package) and splash screen
      (`flutter_native_splash` package) instead of the default Flutter icon.
- [ ] Write real Play Store listing copy + screenshots once content is populated.
- [ ] Consider whether you want Crashlytics/analytics — if you add any third-party SDK later,
      update the Data Safety form to match, since mismatches between the form and actual app
      behavior are Google's most common rejection reason.

### Content policy note
Since this app displays jokes/stories your admin team writes and publishes, **you (not Google)
are responsible for the content itself** meeting Play Store content policies — no hate speech,
no harassment, no sexual content marketed to minors, etc. This is a moderation responsibility on
your admin panel side, not something the app code can enforce automatically.
